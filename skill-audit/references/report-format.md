# 审计报告格式（运行完输出此概述，不展开过程）

```
# 审计报告（概述）

## 优化了哪些技能
| 技能 | 干嘛用的 | 优化了多少 |
|---|---|---|
| `a` | 一句话用途 | 砍 N 处冗余、拆 1 块 |
| `b` | 一句话用途 | 转写 M 句否定、补 K 关键词 |

## 优化条目（每技能一行，列改动点；全库零命中写"无"）
- `a`：砍同义重复 / 拆 references / 删日期戳
- `b`：否定转正向 / 补触发词 / 修死链

## 需补冷跑（缺 cold_run / 缺 version / 版本对不上；只标不代跑；无则写"无"）
- `c`：缺 version 与 cold_run → 需补冷跑（本审计不代跑，交 skill-authoring-guide）

## 待确认（仅"无法自动解决 / 影响功能整体"，无则写"无"）
- `d`：删/合并进 `e`（影响其目标）→ 等你拍板

## 结论
全库通过 / 有 N 条待你拍板
```

## 落区约定
- 报告是**概述总结**，不写过程叙事。
- "优化条目"：常规自动放行项（砍冗余 / 拆文件 / 转写 / 补触发词 / 修过期事实）。
- "需补冷跑"：**独立一节**，放缺状态类（缺 `cold_run` / 缺 `version` / v 号对不上）。审计只标不代跑，交 `skill-authoring-guide`；不占"待确认"两类。
- "待确认"：只放"无法自动解决 / 影响功能整体"两类，等你拍板。
